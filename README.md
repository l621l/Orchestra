# Orchestra — прямой режим разработки

```cmd
py -B orchestra.py --workspace "C:\Users\621\Documents\testOrchestra\test_py_project"
```

Режим по умолчанию — прямой непрерывный цикл на прежнем исполнителе инструментов.
MiMo читает нужные исходники, меняет код и при необходимости запускает ограниченную
команду проекта. Обязательных set_plan, finish_task, remember_work, отдельных
приёмок и требования добавить --smoke больше нет. Модель может планировать кратко
внутри своей работы; раннер не блокирует редактирование до выполнения протокола.
Прямой режим использует общий цикл инструментов Orchestra. Старые режимы
планирования и чередования моделей остаются доступны своим тестам и не участвуют
в запуске CLI.

MiMo работает непрерывно. Sol подключается только для конкретной консультации
по запросу исполнителя или при застревании. Он получает пакет до 6000 символов,
MiMo — непрерывный диалог с реальными вызовами инструментов и результатами.
Диалог не пересобирается перед каждым ответом. Только при приближении к лимиту
входа сокращаются большие результаты с целыми строками исходников, затем
исключаются старые полные пары assistant/tool. Исходное задание, уточнения,
перечень изменений и последний отчёт сохраняются. Разорванные пары не отправляются.

Доступны list_files, read_file, search_text, search_regex, create_file,
replace_text, run_command. Чтение снова имеет обычный лимит до 200 строк,
без принудительных порций по 40. В настройках GUI на вкладке «Git» можно включить
статус и diff, чтение истории и автокоммиты этапов в текущей ветке. Модель выбирает
завершённый этап и сохраняет его отдельным локальным коммитом после проверки.
При пустом `checks` подходит успешная проверка изменённого поведения через `run_command`.
Python-правки с синтаксической ошибкой по-прежнему отклоняются до записи.
Команды выполняются без shell, с ограничением времени и вывода. Проверки нужны
для конкретного поведения, а не как обязательный набор тестов. Ошибка реального
запуска сохраняет частичный статус; успешный импорт зависимости не выдаётся
за проверку приложения. Внешние команды выполняются с правами пользователя,
это не изоляция неизвестного кода.

Сохранились ограничители:

- до 100 API-вызовов и 20000 выходных токенов на запуск;
- раннее подключение сильной модели после серии действий без полезного результата;
- остановка после ограниченной попытки восстановления;
- блокировка повторяющегося неизменного действия;
- входные лимиты: MiMo 96000, сильная модель 16000 символов полного запроса;
- расчётный предел расходов на всё задание $1, включая последующие C.

Цены берутся из pricing.json. Перед API резервируется консервативная оценка
входа и полного ответа; затем учитывается usage, неизвестный расход не считается
нулём. Это предел по настроенным тарифам, а не гарантия счета провайдера.

Перед вводом — короткая местная сводка:

```text
[PAUSE] Direct | Changed files: 2 | Spent: $0.0242/$1.00
C=continue | N: <task>=new | S=status | Q=exit | text=update current task
```

C продолжает. N: текст начинает новое задание; отдельная N запрашивает текст.
S показывает состояние без API. Q выходит. Обычный текст дополняет незавершённую
работу. Когда незавершённого задания нет, обычный текст начинает новое.
Поддерживаются строчные буквы, русская раскладка клавиш и отдельные старые
команды «продолжи»/exit. Классификатора намерений нет.

При первом C после перехода старый checkpoint архивируется в logs/autodev_history.
Исходное ТЗ, уточнения, изменённые пути и учтённый расход сохраняются. Прежний план
сохраняется как legacy_plan для справки, но не блокирует исполнителя и не считается
новым требованием. Игра не переписывается и не откатывается при миграции.

Логи и состояние остаются в logs/. Завершённость определяет исполнитель по
пользовательскому объёму работы и фактическим результатам; отдельного доказательства
полного соответствия всем требованиям нет. Результативность моделей нужно
оценивать реальными прогонами, а не числом тестов самого раннера.

Проверки раннера:

```cmd
py -B -m unittest discover -q
```

## Подключение интерфейса приложения

Запуск окна Windows из исходников:

```cmd
py orchestra_desktop.py
```

Выберите рабочую папку. «Новая задача» и «Отладить» используют текст из поля.
«Продолжить» принимает необязательное уточнение из того же поля.
«Остановить» дожидается завершения уже запущенной локальной операции.
Во время работы видны текущий этап и таймер. В настройках моделей можно включить
«Показывать рассуждения в реальном времени». По умолчанию запрос отправляется
без стриминга. Настройка режима рассуждений MiMo действует независимо.

Настройки провайдеров, список недавних папок, сохранённые задачи и журналы GUI
хранятся в `%LOCALAPPDATA%\Orchestra`. Кнопка «Настройки» открывает редактор лимитов, моделей и провайдеров.
Изменения применяются со следующего запуска. Ключи хранятся в локальном
`config.local.json`. При первом запуске можно скопировать
существующие настройки и историю из папки исходников. Чтобы CLI открывал те же
сохранённые задачи, передайте `--data-dir "%LOCALAPPDATA%\Orchestra"`.

`OrchestraApp.from_directory(config_dir, workspace)` открывает сессию без терминала.
`app.status()` читает сохранённый статус без обращения к моделям. Для запуска
используйте `new_task()`, `continue_task()` или `debug_task()`. Результат содержит
статус, ответ, расход токенов и путь к журналу. `on_progress` получает события
запуска, выбора модели, инструмента, изменений файлов, проверки, расхода и остановки.

Блокировка рабочей папки действует между процессами на одном компьютере. При отмене
`asyncio.Task` приложение завершает журнал и передаёт `CancelledError` вызывающему
коду. Записанные изменения остаются в рабочей папке. При аварийном выходе система
снимает блокировку, а приложение предлагает продолжить с последнего checkpoint.


## Рассуждение и контекст MiMo

На всех рабочих Chat-вызовах MiMo thinking=enabled. Краткий принудительный
финальный отчёт может использовать disabled, чтобы не потратить остаток выхода
на новое рассуждение. reasoning_content сохраняется вместе с ответом, владельцем
(provider/model) и инструментальными вызовами; в следующих запросах к тому же
MiMo поле передаётся полностью, а не обрезается. Sol эти рассуждения не получает.

Старые вызовы без reasoning_content и вызовы другой модели передаются MiMo как
записанные факты с результатами, не как неполная цепочка tool/reasoning.
Рассуждение другого исполнителя не переносится. Инструменты не исполняются повторно.

writer_request_characters увеличен с 24000 до 96000 символов полного запроса.
Размер считается по реальному представлению MiMo, включая reasoning_content.
При нормальном размере история и прочитанные исходники не меняются. У предела
сначала удаляются старые полные пары, сохраняя недавние; только при необходимости
сокращаются большие результаты с целыми строками и точным продолжением.
Сохранённые reasoning_content не режутся. Если даже последний полный ход не
помещается, раннер честно останавливается, не отправляя повреждённую историю.

Сводка на границе окна содержит фактические наблюдения: пути, диапазоны и хеши
прочитанного, найденные объявления, результаты поиска, команды и изменения.
Она не считает чтение реализацией или доказательством завершения.
Общий расчётный лимит $1 и выходной бюджет 20000 токенов сохранены. Рассуждение
учитывается в выходном расходе; это не обещание прежней стоимости каждого запроса.


## Sol по необходимости

Обязательного каждого шестого вызова больше нет. Продуктивная работа остаётся
у MiMo; старые параметры writer_calls/strong_calls сохранены только для старых
исполнителей и не задают расписание в текущем прямом режиме.

MiMo может вызвать ask_expert(question, context) с одним конкретным техническим
вопросом, причиной затруднения и релевантными фактами. В следующем запросе Sol
получает только этот вопрос, контекст и краткую цель. У консультанта нет файловых
инструментов — он не повторяет обход проекта, а даёт диагноз/решение/следующую правку
либо указывает точно недостающие сведения. Ответ ограничен 1536 выходными токенами.
MiMo получает совет как продолжение работы и сам применяет его. Совпадающий вопрос
с тем же контекстом и ревизией исходников использует сохранённый ответ без нового API.

При повторяющемся действии или серии шагов без результата формируется такая же
предметная консультация. Пока продвижения нет, повторный автоматический вызов
не делается. После ограниченной попытки восстановления раннер останавливается.
Новая правка/подтверждённый результат позволяет новую консультацию при новом тупике.
Видимый режим таблицы — Expert on demand, без ложного счётчика шагов 1/6.
Причина обращения записывается в alternating_model.reason и expert_consultation.

Финальный отчёт всегда делает MiMo с рабочей историей, не Sol по очереди.
Если осталось меньше 512 рабочих токенов сверх резерва итогового ответа, начинается
итоговый ответ, а не бессмысленный рабочий запрос на 17 токенов.
Общие ограничения контекста, выхода и расчётных расходов $1 сохраняются.
Проверки маршрутизации работают с поддельным API; самостоятельное качество советов
на реальном проекте следует оценивать отдельно по логам реальных запусков.
